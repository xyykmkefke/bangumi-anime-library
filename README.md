# 番剧库 · Bangumi Anime Library

本地优先的番剧浏览与追番清单。内置 Bangumi 1990–2026 年季度番剧数据，无需账号、无需后端，开箱即用。

当前版本：**v1.6.27**

在线使用：<https://xyykmkefke.github.io/bangumi-anime-library/>

## 功能

- **全库浏览**：按年份、季度、类型、地区、题材筛选，支持评分 / 热度 / 时间 / 名称排序
- **搜索**：多关键词交集、`-词` 排除、拼音首字母、精确匹配优先、标题高亮、搜索历史；支持**别名与多语言文字**——中文简繁互通、日文假名（片假名/平假名等价）、全角半角、英文名与罗马字都能命中同一条目。实测：`Frieren` → 葬送的芙莉莲、`進擊的巨人` → 22 条（简体名）、`葬送的芙莉蓮` → 4 条、`SPY×FAMILY` / `spy family` / `Spy x Family` → 同一批间谍过家家、`我内心的糟糕念头` → 我心里危险的东西（两个不同译名靠别名打通）
- **我的番剧**：想看 / 在看 / 看完 / 弃番四状态；卡片内直接加入或移出、直接输入已看集数、按状态分组、批量标记与移出
- **视图**：结果栏下拉切换网格、列表、看板四列、本季日历（按星期）；按首播季度 / 加入年份 / 观看状态分组；可保存筛选视图
- **发现**：只看已收藏、高分 ≥8.0、隐藏已收藏
- **详情**：大图、元信息、题材与类型 / 地区标签一键筛选、相似推荐、上一部 / 下一部、季度跳转
- **分享**：详情深链、复制链接、系统分享、复制当前筛选视图链接
- **数据**：JSON / CSV / Markdown 导出，JSON 导入合并与无效条目提示，备份时间提醒
- **云同步**：可选接入 GitHub Gist（仅 gist 权限 Token），多设备自动双向合并；删除用墓碑同步，不会“复活”已移出的番剧；网络失败按 10s / 30s / 90s / 5min 退避重试，联网后立即补同步
- **备份提醒**：累计 5 处改动后提示导出，并显示待备份改动数
- **设置与维护**：字号（小 / 标准 / 大）、卡片密度、动效可调，仅存本机；页脚显示数据快照时间，更多菜单可检查新版本；零结果时给出「切到全年」「去掉题材」等一键放宽建议
- **体验**：冷静工具风视觉、明暗主题（可跟随系统）、命令面板（Ctrl/Cmd+K）、键盘与方向键导航、移动端紧凑头部与筛选底部抽屉（高级项默认收起）、44px 触控目标、骨架屏、操作可撤销、离线提示、PWA 离线缓存
- **无障碍**：跳过头部直达列表、弹窗焦点陷阱与 Esc 归焦、状态实时播报
- **加载**：首屏只加载最近一年，全库在首屏后异步补齐（优先 jsDelivr，失败回退本站）；Service Worker 缓存优先，二次打开近乎瞬时

## 装到手机 / 桌面

**iOS（Safari）**：打开在线地址 → 分享 → **添加到主屏幕**，之后从桌面图标全屏启动，图标为紫色「番」。

**Android（Chrome）**：地址栏右侧菜单 → 安装应用。

**桌面（Chrome / Edge）**：地址栏右侧安装图标。

PWA 依赖 HTTPS，双击本地 `index.html`（`file://`）无法注册 Service Worker，只能浏览不能安装。

## 云同步（可选）

追番数据默认只存在本机。想让 iPhone、平板、电脑共用一份清单时：

1. GitHub → Settings → Developer settings → Personal access tokens，创建一个只勾选 **Gists** 读写权限的 Token
2. 打开「我的番剧」→「云同步」，粘贴 Token，Gist ID 留空
3. 点「保存并同步」，会自动创建私有 Gist；另一台设备填入同一个 Token 和 Gist ID 即可

数据直连 `api.github.com`，Token 只保存在该设备的浏览器里，不经过其他服务器。删除、状态变更、观看进度都会双向合并；两端同时改同一条时以最后修改为准，进度取较大值。

## 快速开始

直接双击 `index.html` 即可使用全部核心功能。

如需 PWA 离线缓存，用任意静态服务器打开：

```bash
npx serve .
# 或
python -m http.server 8080
```

然后访问 `http://localhost:8080`。

## 数据

- 数据来源：[Bangumi 番组计划](https://bgm.tv)，通过镜像接口生成
- 数据文件：`data/anime-data.js`（约 9600 部，1990–2026）
- 封面为外链图片，首次查看需联网；离线或失败时显示番名首字占位

## 开发与验收

```bash
npm run verify        # 端到端验收（177 项），需要本机安装 Edge 或 Chrome
npm run check-loading # 加载期搜索行为（全库未就绪时不误报「没有找到」）
npm run perf          # 性能基线（FCP / 首屏可交互 / 交互响应 / 弱网），超预算退出码 1
npm run audit         # 对比度审计；加 -- --check 作为门禁
npm run check-data    # 数据质量校验
npm run doctor        # 发布一致性自检（版本 / 文档 / SW / tag）
npm run tags          # 本地 / 远端 tag 完整性审计
npm run smoke         # 发布后线上冒烟（需网络与 gh）
npm run build-lite    # 重新生成首屏轻量数据
npm run build-pinyin  # 补充拼音首字母（需先 npm install）
npm run fetch-data    # 重新抓取数据
```

`verify.mjs` 会在本机启动静态服务器与无头浏览器，覆盖搜索、筛选、收藏、视图、分享、PWA、无障碍等核心流程。

`perf-baseline.mjs` 用同样的方式测速度：冷启动口径（无缓存、绕过 SW、屏蔽第三方封面图）量 FCP 与首屏卡片可交互，再量五类常用交互的响应，最后在 Slow 3G 下复测首屏。超预算即退出码 1，可用于防止性能退化。

`check-loading-search.mjs` 单独验证加载期搜索：服务端把全库数据延迟 8 秒，在首屏已渲染、全库未就绪的窗口内搜索一个「仅全库存在」的条目，断言提示为「正在加载」而非「没有找到」、搜索词被保留、就绪后无需重搜即自动出结果。之所以独立成脚本而不并入 `verify`，是因为它依赖干净的初始页面状态——`verify` 跑到中段时 SW 已注册、偏好与视图被上百个用例改过，时序类断言在那里不可靠。

**性能基线（v1.6.19，本机无头 Edge）**：FCP 76ms、DOMContentLoaded 64ms、首屏 123 张卡片可交互 174ms；交互 8–30ms；Slow 3G 首屏 7.8s。首屏走 `anime-lite.js`（140KB raw / 35KB br）渲染，全量 `anime-data.js` 在 idle 时后台补齐以支撑全库搜索与跨年浏览。

**数据体积（v1.6.24）**：`anime-data.js` 3.35MB raw / **726KB br**（v1.6.23 为 2.58MB / 519KB）。增长 207KB 来自两块：**别名 352KB raw**（17306 个，是繁体/英文/罗马字能搜到的唯一依据，不能省——实测仅 5.9% 与主名冗余）和**新增 790 条条目 175KB raw**（季度数据自然增长）。GitHub Pages 与 jsDelivr 均按 br/gzip 传输，实际下载量为 726KB。

## 版本

- v1.6.27：季数只从末位 token 抽取（「用自己的名字搜不到自己」）——v1.6.25 的季数折算有一个口径错位：查询侧 `parseQuery` 在 **token 层面**抽季数，条目侧 `seasonOfItem` 在 **整串层面**判断。写「心理测量者3 FIRST INSPECTOR」时，那个 3 是作品名的一部分（第 3 季的副标题写法），查询侧把它抽成「第 3 季」，条目侧整串以 `INSPECTOR` 结尾抽不出序号，于是 `any3` vs `null` 必然不匹配——**用自己的名字都搜不到自己**。全库实测该错位造成中文名 137/9508、原名 158/10437 条自搜失败。修法是「季数在语义上永远位于词尾」，只从查询最后一个 token 抽取，中间的 token 一律按关键词做字面匹配（`心理测量者3` 仍能子串命中），词尾的真序号照常抽取，两种写法都对。修复后中文名自搜未命中 137 → **22**（99.77%）、原名 158 → **31**（99.70%）、别名 994 → **802**（95.37%）、「条目侧季数与查询侧可对齐」397/401 → **400/400**。新增断言「条目用自己的中文名可搜到自己」（9508 条全量，阈值 99.5%）与「季数筛选不混入无关条目」（0/250 误报，带「不存在的作品+第9季 必须 0 结果」反证守卫）；反向验证：撤掉末位规则后自搜断言立刻 FAIL、「条目侧季数与查询侧可对齐」掉回 397/400。剩余 22 条失败经逐条归类为 **13 条「季号与 cour 同时出现」+ 1 条「rest 跨段不连续」+ 8 条「类型词/词尾数字」**：13 条属真实边界（「季」与「cour」是两个语义维度，折叠会把不同作品混在一起）；1 条（「画江湖之不良人第七季：九幽玄天」）是真缺陷——`extractSeason` 删掉季号后把前后拼成一串作 `rest`，而标题里两段原本隔着「第七季」不连续，占比 1/9508，修法属放宽类改动、收益不足，记为已知限制；8 条是类型词（「剧场版」「OVA」被当分类）与词尾数字（「小花仙 第四季 守护天使2」）的边界。verify 175 → **177/177**，SW `yuc-anime-shell-v36`
